# Валидация и ошибки API

Изменённые в #8 маршруты и схемы — в [OpenAPI](openapi.json). Это текущий контракт
точек, distance и источника session/CSRF; полный контракт остальных слоёв расширяется
в #19. Существующие пути, массив создания точек и `totalDistance` сохранены.

## Запросы

- Создание: массив из 1–1000 объектов `name`, `lat`, `lng`. Название содержит
  1–255 Unicode code points, не состоит только из пробелов, без NUL и непарных
  суррогатов. Текст не обрезается и не экранируется перед сохранением.
- Distance: объект `points`, содержащий 2–1000 пар **ровно** `[lng,lat]`.
  Все координаты — JSON numbers, конечные, lng ∈ [−180,180], lat ∈ [−90,90].
  Одинаковые точки допустимы и дают 0; пустой расчёт успехом не считается.
- Пользовательские точки с #7 хранятся в EPSG:4326, поэтому полюса допустимы.
  Ограничения отображения Web Mercator не являются ограничениями хранения или
  геодезического API. Импортированные EPSG:3857 геометрии readonly; при чтении
  backend применяет ST_Transform, а не меняет метку SRID.
- Строки вместо чисел, числа/boolean вместо имени, неизвестные и повторяющиеся
  поля, лишние JSON tokens и malformed JSON отклоняются. Не поддерживаются
  параллельные camelCase/snake_case aliases. `totalDistance` — сохранённое имя v1.
- Парсер также ограничивает вложенность 16, длину строки 4096 UTF-16 units,
  числового token 64, документ 4×1024² входных единиц Jackson. Эти ограничения
  возвращают 400; они не заменяют логические лимиты DTO. Запросы обычно UTF-8.

Весь пакет и все пары проверяются до SQL. Создание остаётся одной транзакцией:
ошибка любой вставки откатывает весь пакет. Ошибки чтения JSON не приводят к записи.
Имя из 255 emoji допустимо без усечения; NUL/непарный surrogate дают 400, а не
ошибку кодирования PostgreSQL или незаметную замену символов.

## Ошибки

Все ошибки приложения используют `application/json`, `Cache-Control: no-store`:

```json
{"code":"invalid_point_id","message":"Используйте полный ID user:<uuid>, возвращённый API."}
```

`code` — стабильный machine-readable идентификатор; `message` — безопасное
пояснение. Ответ не содержит SQL, connection details, имён классов, stack trace,
пароля, session ID или исходного тела запроса. Не используй текст исключения как
message. Неожиданные ошибки журналируются с фиксированной категорией и request ID,
без exception message и stack trace.

| HTTP | Типичные code | Значение |
| --- | --- | --- |
| 400 | `invalid_request`, `invalid_point_batch`, `invalid_distance_request`, `invalid_point_id` | JSON/типы/поля/диапазоны/размер или ID некорректны |
| 401 | `authentication_required` | Нужна аутентификация |
| 403 | `forbidden`, `invalid_csrf`, `read_only_point` | Нет прав, readonly, CSRF или запрет CORS |
| 404 | `point_not_found`, `not_found` | Пользовательской точки или маршрута нет |
| 405 | `method_not_allowed` | Метод не поддерживается маршрутом MVC |
| 406 | `not_acceptable` | Запрошен неподдерживаемый формат ответа |
| 413 | `payload_too_large` | Приложение отклонило слишком большой payload |
| 415 | `unsupported_media_type` | POST требует JSON |
| 500 | `internal_error` | Ошибка SQL/неожиданная внутренняя ошибка |
| 503 | `service_unavailable` | Недоступна БД, не удалось открыть транзакцию или истёк бюджет SQL/транзакции |

Формат применяется и в MVC advice, и в Security/CSRF, CORS rejection и HTTP
firewall. Неизвестные unsafe-маршруты могут получить 403 до MVC405; CSRF403 может
предшествовать проверке входа 401. Это не отключает защиту ради одинакового статуса.
При выключенном CORS обычный публичный GET может вернуть 200 **без** разрешающего
origin-заголовка; запрещённый preflight возвращает 403. Ошибки транспортного уровня
или внешнего proxy не обязаны иметь DTO приложения — клиент использует fallback.

## Удаление и UI

DELETE принимает полный `user:<uuid>` с группами 8-4-4-4-12, в том числе uppercase
hex. Сокращённые формы, которые умеет нормализовать UUID.fromString, отклоняются 400.
`osm:*` запрещён 403, отсутствующий UUID даёт 404, удаление одной строки —204 без тела.
Права редактора и CSRF проверяются раньше операций с данными.

Клиент проверяет HTTP-status до разбора успешного ответа. Общий helper читает
только типизированные `code`/`message`, использует fallback для HTML/несовместимых
тел; сообщения выводятся через текстовые DOM API или обычный alert. Ошибки
distance/слоёв не приводят к обращению к `data.lines/forEach` ошибочного DTO.
Неудачный DELETE не выдаётся за успешный. Сохранение сохраняет черновики, без
авторетрая; при потере подтверждения исход записи остаётся неопределённым (#6).

Проверки включают настоящий PostGIS, неверные структуры/типы/диапазоны, границы
1/2/1000/1001, полюса, Unicode, атомарность и DELETE, принудительно включённые
debug error flags без утечки подробностей. Перевод недоступности БД, ошибки открытия транзакции и таймаутов в 503
проверяется MVC-тестами. `make test-diagnostics` дополнительно проверяет реальный
отказ БД для чтения, создания и удаления, корреляцию и отсутствие утечек
в stdout/stderr; см. [diagnostics.md](diagnostics.md).
Браузерные проверки подтверждают реальные ответы фильтров, UI-причины ошибок
слоёв/distance, повтор расчёта и удаление точки другим клиентом.

Геослои также принимают optional bbox/zoom:400 `invalid_spatial_query`,
413 `spatial_limit_exceeded`/`spatial_geometry_limit_exceeded`,503 `spatial_query_timeout`.
Точный контракт и бюджет выдачи — [spatial-queries.md](spatial-queries.md), OpenAPI.
