# Демонстрация курсового проекта

Краткий сценарий для проверки и презентации приложения. Подготовка окружения —
в [README](../README.md#быстрый-старт), подробный HTTP-контракт — в [api.md](api.md).
Для обычного просмотра достаточно `make init-env` и `make dev`.

## Сценарий

1. **Показать данные.** Открой UI, включи точки, дороги и полигоны. На чистой demo-БД
   доступны 3 точки, 2 дороги и 2 полигона Железногорска. Приблизь центр города;
   движение карты меняет bbox/zoom запросов. Начальный просмотр не разрешает запись.
2. **Войти редактором.** Останови приложение (`Ctrl+C`), выполни `make init-editor`
   и снова `make dev`. Войди через ссылку интерфейса с реквизитами своей приватной
   `.env`. Браузерная сессия редактора не переживает перезапуск сервера — войди заново.
3. **Создать точку.** Включи добавление, введи широту `52.3378` и долготу `35.3478`,
   нажми «Добавить по координатам». Назови черновик «Пункт наблюдения», сохрани.
   Обнови страницу, снова включи слой точек: сохранённый объект должен остаться.
4. **Измерить расстояние.** Включи выбор для расчёта. Выбери последовательно
   OSM-точку «Аптека» и «Пункт наблюдения», нажми «Рассчитать».
   Нажатие на сегмент показывает popup. Для этих координат API вернул
   `211.50716966` м, интерфейс округлил до `211.51 м`.
   Это геодезический отрезок на сфероиде WGS84; дороги в расчёте не участвуют.
5. **Удалить свою точку.** Выключи выбор расстояния, выбери пользовательскую точку
   и выполни удаление. После обновления страницы и повторного включения слоя
   она должна отсутствовать. У OSM-точки нет разрешения на удаление.

Для проверки сохранности перед последним шагом можно выполнить `make db-reset-demo`
на работающей БД: reference-снимок восстановится, пользовательская точка останется.
Затем останови приложение, выполни `make db-down` и снова `make dev`: тот же volume
сохраняет UUID/координаты, а серверную сессию потребуется создать повторным входом.
Не удаляй volume для обычного сброса demo.

Эталонные проверки алгоритма и их независимый допуск находятся в
[testing.md](testing.md). Число на скриншоте иллюстрирует один сценарий;
точка, добавленная другим кликом, закономерно даст другую длину.

## Скриншоты

- [map-overview.png](images/map-overview.png): начальное readonly-состояние,
  все три слоя, исходный zoom 13 и demo 3/2/2.
- [distance-editor.png](images/distance-editor.png): сессия редактора,
  сохранённая пользовательская точка, выбор «Аптека» → «Пункт наблюдения»,
  рассчитанный сегмент; zoom 15 (два нажатия `+` от начального вида).

Оба изображения сняты 2026-11-04 настоящим Chromium при viewport 1536×960
с запущенным Spring Boot и PostGIS. Это снимки текущего Svelte-интерфейса;
DOM, подписи и результаты не подменялись. Для фоновой карты использован обычный
сервис OSM с видимой атрибуцией. Данные/карта: ©
[OpenStreetMap contributors](https://www.openstreetmap.org/copyright),
[ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/). MIT для кода
не заменяет условия сторонних геоданных и тайлов.

При существенном изменении показанного интерфейса повтори сценарий на собственном
изолированном demo-контуре и обнови изображения. Не включай пароль, `.env`,
cookie, URL с реквизитами или личные данные в кадр. У браузерных regression tests
тайлы отключены; эти иллюстрации сняты отдельно с настоящим тайловым фоном.

## Что проверено для README

2026-11-04 инструкция проверена на чистом локальном clone commit
`9db2a2f8b127defb477ac51169e856a8972934b1` (UI/backend перед документационным #22).
До создания `.env` рабочая копия была чистой; PostGIS получил новый именованный
volume, а не прежнюю БД или test tmpfs. Для изоляции использованы отдельный
Compose project и свободные localhost-порты: имя `leaflet-readme-22-132772`,
`DB_PORT=50679`, `SERVER_PORT=54871`. На обычном запуске используются порты README.

Проверены `make init-env`, `make dev`, `make init-editor`, повторный запуск,
`make db-reset-demo`, `make db-down`, `make build` и `make check`. В браузере
пройдены создание по координатам, сохранение, reload, distance, удаление и проверка
отсутствия после reload. Reset и перезапуск сохранили полный API-объект с UUID;
необработанных ошибок браузера не было. Readiness отвечал UP, `.env` имела режим 0600.

Использованы полный JDK 25, Node 22.23.4 и уже заполненные caches Maven;
это проверка чистого checkout и пустой БД, а не загрузки всех зависимостей
на машине без сети. Свой процесс, контейнер, сеть и QA-volume после проверки
удалены; рабочая `.env` автора не использовалась. Обязательный CI описан в
[ci.md](ci.md); эта ручная проверка не заменяет весь набор тестов.
