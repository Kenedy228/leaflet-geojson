# Frontend: Svelte 5 и Leaflet

Один экран на Svelte 5 + TypeScript strict + Vite, без маршрутизатора.
Leaflet 1.9.4 и CSS входят в bundle; внешние JS/CSS и Bootstrap не нужны.
Серверный контракт остаётся Spring Boot API. Геоданные и названия проходят
runtime-проверку в `src/lib/api.ts` до передачи компонентам.

## Разработка и сборка

Нужен Node 22.23.4 (см. `.node-version`), npm и запущенный backend:

```sh
make dev
# В другом терминале из корня:
npm --prefix frontend ci --ignore-scripts
make dev-frontend
```

Открой http://127.0.0.1:5173. Vite обслуживает GET `/login` из `login.html` с HMR; POST `/login`, `/api` и `/logout` проксируются на
http://127.0.0.1:8080, сохраняя browser origin и session cookie. Если backend
использует другой порт, задай `API_PROXY_TARGET` только процессу dev-сервера:

```sh
API_PROXY_TARGET=http://127.0.0.1:8090 make dev-frontend
```

Это настройка инструмента разработки, не публичный URL в bundle. Для входа
редактора открывай `/login` на том же Vite origin; после входа redirect `/`
возвращает на UI. Никакие DB/editor secrets в `VITE_*` не передаются.
Production JAR всегда обслуживает UI и API с одного origin.

```sh
npm --prefix frontend run check  # svelte-check + strict TypeScript
npm --prefix frontend run lint   # ESLint Svelte/TS и browser tests
npm --prefix frontend test       # Vitest: transport, state, map lifecycle
npm --prefix frontend run build  # frontend/dist, статическая production-сборка
npm --prefix frontend run dev    # HMR dev server
```

`make build`, `make run`, `make dev`, `make verify` и прямые lifecycle-команды
Maven Wrapper устанавливают npm-зависимости из lockfile и строят Vite на фазе
`generate-resources`. Maven копирует **только dist** в static resources.
На `initialize` удаляется старый `target/classes/static`, чтобы удалённые classic
scripts и предыдущие hash assets не оставались доступны в повторной сборке.
Первый запуск требует сети для npm/Maven; готовый JAR Node не требует.

## Состояние и взаимодействие

`App.svelte` создаёт собственный `AppModel`, завершает его запросы при уничтожении.
Компоненты отвечают за слои, редактор черновиков, дистанцию и Leaflet. Нет общих
изменяемых глобальных переменных, ручной синхронизации UI DOM и test-only hooks.
DOM создаётся вручную только внутри Leaflet (popup и доступные SVG paths).
Названия всегда выводятся как текст, включая подписи сегментов расстояния.

- Просмотр, добавление и выбор дистанции имеют согласованные переключения:
  добавление и выбор дистанции взаимно исключаются. Клик по сохранённой точке
  в режиме добавления не создаёт случайный черновик.
- Черновики сохраняются при выключении добавления и logout; удаление черновика
  удаляет его строку и маркер. Координатная форма даёт клавиатурную альтернативу
  клику карты. У каждого черновика стабильный строковый ID.
- Сохранение отправляет снимок видимых полей, блокирует повторную отправку и
  редактирование отправленных строк. Поздние черновики остаются. Только
  подтверждённый полный ответ с уникальными серверными ID удаляет снимок;
  ошибка/неопределённый результат сохраняет его без автоматического повтора.
- Подтверждённые создания/удаления учитываются отдельно от GET, поэтому поздний
  ответ загрузки не откатывает собственную запись. Переключатель points управляет
  всем слоем, включая новые точки с серверными ID. Более поздний успешный GET
  гасит предыдущие overlays и учитывает изменения других редакторов.
- Слои используют AbortController и номер запроса; скрытие отменяет запрос и
  очищает данные. HTTP, offline, timeout, JSON/GeoJSON ошибки видны с кнопкой
  повтора. Состояние checkbox отражает намерение показать слой.
- Выбор для удаления отделён от списка дистанции. Скрытие points, выход из
  дистанции и сброс очищают выбор/линии и обесценивают поздний ответ.
  Расчёт использует снимок координат; новый расчёт заменяет предыдущий.
- GeoJSON и distance передают `[lng, lat]`; Leaflet получает `[lat, lng]`.
  Расстояния в метрах вычисляет backend на WGS84 geography; это сумма сегментов,
  не дорожный маршрут.
- Права проверяются перед каждой записью вместе со свежим CSRF. При отказе
  сохраняются черновики, состояние доступа обновляется. Logout остаётся
  стандартным Spring redirect; клиент ожидает его как ответ без JSON. Порядок
  ответов session также проверяется: старый ответ не восстанавливает доступ и
  фоновые обновления после ошибки не вытесняют выполняющийся logout.

Карта создаётся после mount, хранит внешние объекты без глубоких реактивных proxy,
освобождает слои, обработчики, ResizeObserver и экземпляр карты при unmount.
Панель доступна с клавиатуры; paths карты имеют имена и поддерживают Enter/Space.
На узком экране панель и карта располагаются вертикально, атрибуция OSM видима.

## Проверки и ограничения

Vitest проверяет transport/state и повторное монтирование настоящего Leaflet.
Chromium проверяет UI с настоящими API/PostGIS, злонамеренные названия,
снимки сохранения, гонки ответов, logout, клавиатуру и мобильную ширину.
Это проверки конкретных сценариев, не сертификат WCAG или всех браузеров.
Публичный сервис тайлов не участвует в тестах; без сети фон карты недоступен,
но локальные геоданные и операции приложения работают. Используется HTTPS URL
`https://tile.openstreetmap.org/{z}/{x}/{y}.png`, обычный browser cache/referrer и
видимая атрибуция, без prefetch/offline download; см. [OSM Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/).

`npm audit` сообщает два low finding у dev-зависимости `deepmerge`, используемой
Svelte Vite plugin для объединения доверенной конфигурации сборки (GHSA-gcqx-w48m-w2h4).
Upstream исправления пока нет; пакет не входит в runtime bundle. Не передавайте
недоверенные данные в build config. Обновить после исправления upstream;
не заменять зависимость несовместимым override ради подавления отчёта.

Обновление слоёв по viewport и пределы детализации — [spatial-queries.md](spatial-queries.md).
При pan/zoom сохраняются черновики и координатные снимки маршрута; ответы старой
области отменяются, а превышение 500 объектов требует сузить область вместо
получения незаметно обрезанного слоя.
