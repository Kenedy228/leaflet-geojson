# Критерии готовности и границы результата

Проект предназначен для локальной презентации курсовой работы и GitHub-портфолио.
Успешный запуск процесса, корректность геометрии и успешный CI — разные проверки;
каждую нужно подтвердить отдельно. Порядок работ ведётся в [roadmap #20](https://github.com/Kenedy228/leaflet-geojson/issues/20).

## Проверяемая готовность

| Критерий | Как подтвердить |
| --- | --- |
| Чистый checkout запускается по README | Полный JDK 25, закреплённый Node, Python/Make/Compose; `make init-env`, `make dev`, затем UI и readiness UP. Повторный запуск сохраняет данные |
| Demo воспроизводимо и не владеет user points | `DemoDatasetTests`: Flyway/seed, повторный seed, отказ при чужом OSM и сохранность `app.user_points`; правила [infra](../infra/README.md) |
| Основные сценарии завершены | Браузерные тесты: просмотр слоёв, создание → сохранение → reload → выбор → distance → удаление → проверка отсутствия; ошибки, гонки ответов, logout и клавиатура |
| Геометрия и расстояния корректны | Настоящий PostGIS, WGS84/SRID, все поддерживаемые типы; независимые эталоны сегментов и total с допуском 0.02 м, [testing.md](testing.md) |
| Контракт соответствует API | Валидация [openapi.json](openapi.json) и примеры [api.md](api.md) против собственного приложения/PostGIS; body, статус, security и заголовки проверяются отдельно |
| Отказ диагностируется безопасно | `make test-diagnostics`: startup failure, SQL failure, корреляция, DB outage/recovery, liveness/readiness, graceful shutdown и отсутствие секретных canaries |
| Обязательные проверки зелёные | `make ci` и актуальный `Monorepo checks` для проверяемого commit; [ci.md](ci.md). Benchmark запускается отдельно |
| Публикуемые файлы безопасны | Проверить staged diff: без `.env`, дампов, личных данных и секретов; fixtures синтетические либо лицензированное reference demo. Код и данные имеют разные лицензионные условия |
| Описание соответствует состоянию | README ссылается на архитектуру/модель/API; известные ограничения приведены ниже. Перед презентацией сверить открытые issues, а не считать весь roadmap закрытым |

Автотесты подтверждают перечисленные сценарии. Наличие зелёного CI не является
гарантией отсутствия любых дефектов, полной доступности или пригодности данных
для навигации. Перед презентацией проверь пользовательский сценарий в выбранном
браузере и отсутствие известных блокирующих issues.

## Измеренные показатели

Сохранённый [отчёт от 2026-11-01, 05:50:45 UTC](benchmarks/2026-11-01-spatial.json)
относится к реализации пространственных запросов задачи #9. Это исторический
локальный прогон, а не новое измерение текущего commit и не SLA.
Его [рецепт и production SQL](../backend/src/test/java/com/github/gis/geo/SpatialQueryBenchmark.java)
воспроизводятся командой `make benchmark-spatial` на отдельной tmpfs БД.

Условия: Linux amd64, 16 логических CPU, Java 25.0.5, PostgreSQL 17.5,
PostGIS 3.5.2; 50000 OSM-точек, 1000 пользовательских, 10000 дорог и 5000
полигонов. Viewport `35.3,52.3,35.4,52.4`, zoom 13; исходные городские дороги
имеют 80 вершин, полигоны — 81. Первый образец записан отдельно после
INSERT/ANALYZE; затем 20 прогретых SQL/HTTP образцов, p95 по nearest-rank.
Это не cold-cache тест и не нагрузочный тест конкурентных редакторов.

| Слой | Объектов | Размер UTF-8 ответа, байт | SQL p95, мс | HTTP p95, мс |
| --- | ---: | ---: | ---: | ---: |
| Точки | 380 | 63960 | 1.914 | 10.037 |
| Дороги | 200 | 198181 | 27.154 | 33.391 |
| Полигоны | 100 | 37701 | 7.729 | 11.416 |

Для distance на 1000 точек HTTP p95 составил 15.573 мс. SQL-замеры используют
EXPLAIN ANALYZE/BUFFERS с накладными расходами profiling; HTTP включает передачу
полного тела. Селективные планы используют GiST индексы; overflow fixture даёт
413. Заранее выбранные локальные цели — SQL p95 ≤200 мс, HTTP p95 ≤500 мс,
ответ ≤2 MiB — выполнены на этом наборе. Новые изменения и другое оборудование
требуют повторного измерения. Подробности и все образцы — [spatial-queries.md](spatial-queries.md).

## Известные ограничения

- Один общий локальный редактор и общие точки. Персональных аккаунтов,
  владельцев объектов, аудита действий и разрешения конфликтов редактирования нет.
  Последующий успешный GET отражает актуальную БД; это не realtime collaboration.
- Черновики и выбор находятся в памяти страницы. Reload их теряет. У записи нет
  ключа идемпотентности: после потери ответа сначала проверь созданные точки,
  затем решай о повторе. Пакет либо записан целиком, либо откатывается.
- Distance — сумма геодезических сегментов, без маршрутизации по дорогам,
  высот и дорожных ограничений. Допуск эталонов не характеризует точность OSM.
- Лимит слоя — 500 объектов; после обработки максимум 5000 вершин на объект
  и 20000 на слой. При превышении нужно сузить область; пагинации и полного
  экспорта нет. OSM Web Mercator ограничен широтами ±85.0511287798066°;
  пользовательские точки EPSG:4326 поддерживают полюса.
- Demo — небольшая область Железногорска. Полный внешний OSM-импорт выполняется
  отдельной процедурой с проверкой схемы; данные OSM доступны API для чтения.
  У полигонов/дорог нет поддерживаемого API редактирования.
- Без сети фон OSM может отсутствовать; локальные векторы и вычисления работают.
  Тайлы не скачиваются для offline. Исходники JS/CSS поставляются в bundle.
- Автоматический browser gate использует Chromium и конкретные сценарии axe/
  клавиатуры. Совместимость со всеми браузерами и полная WCAG-сертификация
  не заявляются. Применимые проверки и dev advisory — [frontend.md](frontend.md).
- БД и приложение рассчитаны на доверенный локальный запуск. Публичный deployment,
  TLS termination, HA, capacity planning и внешнее наблюдение не реализуются
  в рамках этой курсовой. Инструкции не следует принимать за руководство
  безопасной публикации сервиса в Интернет.
- У программного кода пока не выбрана лицензия; OSM demo имеет собственную
  атрибуцию и ODbL. Перенос данных не заменяет выбор лицензии для кода.

Итоговое оформление главной страницы и демонстрационного маршрута выделено в
[README #22](https://github.com/Kenedy228/leaflet-geojson/issues/22).
