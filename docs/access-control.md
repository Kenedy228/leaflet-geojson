# Доступ к общим точкам

Анонимный посетитель читает слои и рассчитывает расстояния. Роль `EDITOR` создаёт
и удаляет общие точки из `app.user_points` только при включённой оператором записи.
OSM-точки readonly даже для редактора. Регистрации и персонального владения нет.

## Настройка

`make init-env` → `make dev` по умолчанию даёт **readonly**, включая demo-профиль.
Для демонстрации редактирования останови приложение, выполни `make init-editor`
и снова `make dev`. Команда включает `EDITING_ENABLED=true`, устанавливает
`EDITOR_USERNAME=editor` и генерирует отдельный `EDITOR_PASSWORD` в `.env` (0600).
Пароль не печатается: прочитай его локально в файле и введи в серверную форму
«Войти как редактор». Не копируй секрет в Git, issues, frontend или URL.
Повторная команда сохраняет пароль редактора и реквизиты БД. Окружение приоритетнее
`.env`; shell-подстановки в этом файле не выполняются.

Вместо команды можно задать переменные окружения. При включённой записи нужны
непустой username без пробелов (до 64 символов) и пароль 16–72 байта UTF-8.
Неполная настройка прерывает запуск без вывода пароля. Сервер хранит in-memory
учётную запись со стандартным BCrypt, cost 12; bootstrap пароль в окружении/`.env`
остаётся секретом. Default-пользователь Boot, Basic auth и remember-me не включены.

Для readonly задай `EDITING_ENABLED=false` и перезапусти приложение: запись будет
запрещена независимо от роли. Перезапуск инвалидирует in-memory сессии. Для ротации
замени пароль в приватной конфигурации и перезапусти JVM; повторный `init-editor`
не заменяет существующий пароль. Работающая JVM не перечитывает `.env`.

## HTTP и CSRF

| Запрос | Требования |
| --- | --- |
| GET/HEAD страницы, static и слои | Публичный доступ |
| POST `/api/v1/osm/distances` | Публичное вычисление; единственное исключение CSRF |
| POST `/api/v1/osm/points/add` | Включённая запись + сессия EDITOR + CSRF |
| DELETE `/api/v1/osm/points/{id}` | Те же требования; только `user:<uuid>` |
| GET `/api/v1/session` | Публичное состояние текущей сессии/CSRF, `Cache-Control: no-store` |
| GET/POST `/login` | Серверная форма, POST с CSRF |
| POST `/logout` | CSRF, инвалидирование сессии |

Session cookie `JSESSIONID`: HttpOnly, SameSite=Lax, timeout 30 минут неактивности;
ID меняется при входе. JS не читает эту cookie и не хранит пароль в браузерных
storage. Контур предназначен для localhost HTTP. Публичное развёртывание потребует
отдельной задачи с HTTPS и защитой от перебора; сейчас оно не предусмотрено.

`/api/v1/session` возвращает `editing_enabled`, `can_edit`, `csrf_header`,
`csrf_token`. CSRF-токен не является паролем, он привязан к текущей сессии.
Получай его перед входом и заново после входа/выхода: старый токен после успешного
входа больше не подходит. Изменяющий API-запрос передаёт cookie и CSRF-заголовок.
UI обновляет состояние перед записью. При 401/403 автоматической повторной записи
нет; черновики сохраняются, кнопки учитывают потерю прав и незавершённые запросы.

Нет аутентификации — API 401 вместо HTML-редиректа; нет прав/readonly/ошибка CSRF —
403. CSRF может вернуть 403 до проверки аутентификации. Для редактора сохраняются
прежние 201/204 и ошибки валидации/OSM/отсутствующих ID.

Редактирование поддерживается только **same-origin**. CORS не включает credentials
и CSRF-заголовок, поэтому разрешённый отдельный сайт не получает доступ к сессии
редактора. Не расширяй CORS и не отключай CSRF ради входа.

Интеграционные тесты используют настоящий изолированный PostGIS: отказ анонимному,
reader, readonly editor, отсутствующему/неверному CSRF без изменений строк;
реальный cookie login, смена session ID, старый токен, CRUD, logout и replay.
SQL-миграции/backup/restore требуют отдельного доступа оператора к БД и не получают
прав через браузерную роль.

Проверено для #4: `make verify` — 55 backend-, 6 frontend- и 4 CLI-проверки,
сборка JAR. Chromium в двух изолированных контурах подтвердил readonly, вход и
смену session cookie, CSRF CRUD, запрет повторной отправки при pending-запросе,
сохранение новых черновиков, потерю прав после выхода в другой вкладке и UI logout.
Новые элементы доступа проверены с клавиатурой и scoped axe без нарушений;
это не аудит всей legacy-страницы. Независимое review не выявило обходов защиты.
